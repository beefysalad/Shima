## Findings and follow-ups
- **Hands-off window for the CPU rows:** 18:25:12 to 18:28:48 on 2026-11-22 (strict idle 18:25:12 to 18:26:19, playing run 18:26:26 to 18:28:48). Everything else ran before it; the Mac was kept awake with `caffeinate -dimsu` and the screen did not lock (`locked=0/0` in the playing run).
- **Wing overlap WARN (accepted):** the first status item windows start at x=854-855, not the plan's 860, so the live right wing (ends at x=858) overlaps the item's window by 3 to 4 pt. Item windows include padding; check by eye. That first item is Shima's own capsule (its menu opens at x=851). If wanted later, narrow the right wing by 4 pt or accept.
- **`verify-alignment.sh --menus` limitation:** it skips windows owned by Shima, so when the first status item is Shima's own menu it reports `no menu window` (exit 1) although the menu opened. Follow-up: have the script accept Shima-owned layer 101 windows away from the island, or document the click target.
- **Fake mode and quit state:** after `fake quit` the fake ignores broadcasts until `fake launch` (plan note 6). The plan's Step 5 drive line needs `fake launch;` first when the previous run ended in quit.
- **Criterion 1 not strictly measured:** the 5x timed protocol was not run; see the numbers in row 1 (max 445 ms from the logs). A strict run is still available if wanted.
- **Not done (HUMAN):** typing in TextEdit with the live island; M0 manual focus mode; M0 Apple menu check; real-mode plain strict idle with Spotify quit; real-Spotify `--playing` CPU run.
- **Equalizer WindowServer cost** about +6.7 points at 20 fps in this run (accepted).
